Abstract
Large Language Models (LLMs) are increasingly deployed on edge
devices to address privacy and latency concerns in modern Web
applications. While numerous studies focus on inference frame-
works, the critical problem of tuning runtime configurations re-
mains largely underexplored. This endeavor is particularly chal-
lenging on edge devices due to severe budget limitations and the
dynamic variability of system resources.
To address these challenges, we draw upon key insights regard-
ing parameter sensitivity, configuration transferability, and rank
stability to propose LaTune, a lightweight and adaptive tuning
framework. LaTune is designed to efficiently find optimal runtime
configurations by incorporating three complementary components:
parameter selection to focus on the most impactful parameters,
knowledge transfer to leverage historical data for accelerated search,
and two-stage optimization to dynamically select the best configu-
ration based on real-time resource constraints. Experiments across
four edge devices and LLMs show that LaTune achieves up to 3.93×
higher hypervolume and 6.90×throughput gains over baselines.
It accelerates tuning efficiency by 2–3×, converging within 10–20
iterations, and ensures robust execution under heavy contention
where static methods fail. Our code is already open-sourced at
https://github.com/pkuaiweb/LaTune.

1 Introduction
Large Language Models (LLMs) are increasingly embedded in mod-
ern Web applications, driving services such as personalized search,
recommendation, and interactive content creation [14, 30, 39, 49,
62]. However, the high computational demand of LLM inference
means that most systems still rely on cloud-based deployment. This
design enables efficient processing but also requires transmitting
large volumes of user data to remote servers, raising concerns about
privacy, latency, and network dependency. Recently, there has been
a growing shift toward running LLMs on edge devices [37, 63]
such as personal computers, edge servers, and IoT nodes. With
lightweight edge inference engines like llama.cpp [1], models can
now run locally on consumer-grade hardware, enabling privacy-
preserving and low-latency Web intelligence without full reliance
on the cloud.
To ensure a smooth user experience, it is equally important that
local inference runs efficiently. Modern inference engines incor-
porate a variety of optimization techniques, including continuous
batching [16, 51, 65], flash attention [17, 18, 46], and chunked pre-
fill [4, 5, 76], to accelerate inference. At the same time, runtime
parameters such as batch size and thread count also have a strong
impact on performance [7, 41, 66]. Together, the selection of opti-
mization techniques and the tuning of runtime parameters define
the runtime configuration of the inference engine, which plays a de-
cisive role in overall performance. A desirable configuration should
achieve high throughput, i.e., a faster token generation rate during
on-device inference, while keeping resource consumption such as
GPU memory and CPU usage within acceptable limits. However,

since edge devices differ widely in architecture and capacity [57].
Therefore, adaptive tuning is essential for achieving efficient and
stable inference on diverse edge devices.
However, tuning configurations on resource-constrained devices
presents two unique challenges. The first is the limited budget [63]
for tuning. Each evaluation involves costly operations such as model
loading, decoding, and monitoring, which compete with user tasks
for computation. On devices with limited CPU capacity, a tuning
process that runs too long may disrupt normal usage or even be
terminated by the operating system. The second challenge lies in
the variability of device resources [54, 64, 72]. Edge devices are
often affected by background processes, causing fluctuations in
available memory and compute capacity. As a result, the feasible
configuration space is dynamic, and settings that perform well in
one run may degrade quickly under different resource conditions.
To address these challenges, we propose LaTune, a lightweight
adaptive tuning framework that efficiently identifies optimal config-
urations under tight budgets while maximizing runtime throughput.
Our design leverages three key insights. First, as only a small subset
of parameters dominates performance, we restrict the search to
these high-impact factors to minimize tuning costs. Second, recog-
nizing that high-performing configurations often generalize across
tasks, we reuse historical data to accelerate the tuning process.
Third, the stability of configuration rankings under resource fluc-
tuations allows us to utilize configurations learned under stable
conditions to guide dynamic runtime selection.
Building on these insights, LaTune adopts a simple yet effective
strategy that includes three complementary components. To cope
with the limited tuning budget, LaTune first performs parameter
selection, identifying the parameters that have the greatest impact
on throughput and resource use, thereby reducing search com-
plexity and improving efficiency. To mitigate the cost of exploring
from scratch, LaTune further applies knowledge transfer, which
reuses high-performing configurations from previous tuning tasks
as warm-start candidates under similar workload and hardware
conditions. Finally, to handle fluctuating resources, LaTune intro-
duces two-stage optimization, where the system learns the Pareto
front under stable conditions and selects suitable configurations
at runtime according to the current resource state. Together, these
components enable LaTune to balance throughput and resource uti-
lization while maintaining robustness across diverse and dynamic
edge environments.
We conduct extensive experiments to evaluate LaTune across
diverse settings, covering four LLMs with distinct architectures
and quantization levels deployed on four heterogeneous edge de-
vices. To rigorously test adaptability, we simulate three distinct
resource levels (Low, Medium, High) and compare LaTune against
four representative baselines: Default, GA [24], ResTune [70], and
SCOOT [15]. Experimental results demonstrate that LaTune consis-
tently outperforms all baselines across varying devices and resource
conditions. Specifically, it achieves 1.47×–3.93×higher Hypervol-
ume compared to default settings and surpasses the strongest base-
lines by 1.05×–6.90×in throughput. Notably, LaTune exhibits su-
perior robustness, maintaining stable performance under high-load
scenarios where static configurations fail completely. In terms of

efficiency, it identifies high-quality Pareto fronts within 10–20 itera-
tions, converging 2–3×faster than prior methods. Further ablation
studies confirm the essential contributions of parameter selection,
knowledge transfer, and two-stage optimization to these gains.
In summary, the main contributions of this paper are as follows:
•To the best of our knowledge, this is the first work that systemat-
ically studies configuration tuning for LLM inference engines on
edge devices, addressing the challenges of resource-constrained
and dynamic environments.
•We propose LaTune, a lightweight and adaptive tuning method
that incorporates practical design optimizations to make on-
device tuning efficient and responsive to changing resources.
•We conduct extensive experiments across diverse models, hard-
ware platforms, and resource settings, demonstrating that LaTune
finds better configurations with fewer evaluations, and achieves
higher throughput and robustness than existing methods.
2 Background and Motivation
We first review the architecture of on-device LLM inference engines
and the challenges inherent in configuring them. We then present
a measurement study yielding empirical insights that guide the
design of LaTune.
2.1 On-Device LLM Inference Engines
Running LLM inference directly on edge devices provides an ef-
fective alternative to cloud-based deployment for Web applica-
tions [63]. Processing queries locally avoids data transmission, en-
hancing privacy and reducing latency for Web services. It enables
continuous operation even in bandwidth-limited or offline environ-
ments. This capability enhances the responsiveness and reliability
of edge-intelligent applications that require real-time interaction.
To support such deployment, several inference engines have
been developed to execute LLMs efficiently on local hardware. Rep-
resentative examples include llama.cpp [1], MLC-LLM [53], and
TensorRT-LLM [3]. llama.cpp is a lightweight C/C++ implementa-
tion that enables quantized model inference on CPUs and GPUs,
serving as the backend for local Web frameworks such as Ollama [2].
MLC-LLM extends machine-learning compilation to support unified
deployment across heterogeneous hardware, while TensorRT-LLM
integrates NVIDIA’s TensorRT library to deliver optimized GPU per-
formance. In contrast, cloud-oriented systems such as vLLM [29]
and SGLang [75] are designed for large-scale GPU clusters and
therefore fall outside the on-device inference scope of this work.
Despite differences in implementation details such as memory
management and task scheduling [42], modern inference engines
are commonly organized around the four domains of model prepa-
ration, inference execution, system management, and service man-
agement [32, 42, 58]. During inference, they expose a set of tunable
parameters that jointly affect throughput and latency [15]. As sum-
marized in Appendix Table 2, these parameters can be organized
into four hierarchical levels according to their functional scope.
In this work, we focus on optimizing runtime-level parameters
that directly influence performance while keeping model quality
and service semantics unchanged. Specifically, we exclude model-
compression options (e.g., quantization precision) and service-layer
configurations that are irrelevant to inference efficiency.

On-device inference operates under highly dynamic environments
and diverse workloads, making universal tuning strategies difficult
to design. To understand how configuration parameters interact
with varying hardware and resource conditions, we conduct a com-
prehensive measurement study that provides empirical insights to
guide adaptive tuning.
Experimental Setup. We conduct measurements using llama.cpp [1]
on two representative edge devices: a PC with an RTX 3060 and a
Mac with an Apple M4. We evaluate Qwen3-4B-Q4 and Phi-Mini-
MoE-Q8, which differ significantly in architecture. To cover di-
verse workloads, we employ short conversational queries and long-
document summarization [47]. Furthermore, we simulate four lev-
els of system load by applying controlled stress to mimic varying
resource availability. With the context length fixed at 1024, we
measure average throughput (tokens per second, TPS) and VRAM
usage.
Insight 1: Uneven parameter contribution. A major challenge
in on-device tuning is the large number of exposed parameters,
many of which have negligible impact on performance. We conduct
a one-factor-at-a-time (OFAT) sensitivity analysis [44] using the
default setup as baseline and vary six representative parameters
individually. As shown in Figure 1, the impact is highly uneven:
increasing gpu-layers improves TPS by 43.4% with minimal GPU
overhead, while disabling kv-offload decreases it by 15.5%. Other
parameters, such as parallel and no-cont-batching, show little
effect. Such findings highlight that only a few key parameters dom-
inate efficiency, motivating a focused search on influential factors
rather than uniform exploration.

Insight 2: Transferability of Optimal Configurations. Another
difficulty lies in the cost of tuning from scratch for each device or
workload. To examine reusability, we construct five tuning tasks
that differ in hardware, model, and workload. Each empirically
optimal configuration is tested across other tasks. As shown in
Figure 2, several configurations perform well beyond their orig-
inal setting, e.g., conf.B even surpasses local optima on tasks A
and C, whereas some fail under tighter resource limits. It suggests
that high-performing configurations can be transferred across sim-
ilar tasks to warm-start new tuning processes, but effective reuse
requires awareness of task similarity.
Insight 3: Rank Stability Across Resource Conditions. End-
device resources fluctuate due to background activities, making
static configurations unreliable. We simulate four levels of system

der each. Figure 3 shows that the relative TPS order among valid
configurations remains stable, yet higher load reduces TPS and can
cause some configurations to fail because the available resources
are insufficient. This stability indicates that statically identified con-
figurations can effectively guide runtime tuning, reducing repeated
exploration when resource conditions change.
3 Problem Formulation
Efficient on-device LLM inference requires selecting proper run-
time configurations that balance throughput and resource use under
changing hardware conditions. However, these configurations de-
pend on multiple interacting parameters and a dynamic resource
environment, making the tuning process a continuous optimization
problem rather than a one-time search.
We formalize the tuning problem as follows. Let the space of all
tunable parameters be Θ= Θ1 ×Θ2 ×···×Θ𝑚, where Θ𝑖 repre-
sents the domain of the 𝑖-th parameter exposed by the inference
engine. A configuration P= (𝑝1,𝑝2,...,𝑝𝑚)is a point in this space,
where each 𝑝𝑖 ∈Θ𝑖 corresponds to a specific setting of parameter 𝑖.
The inference performance of P can be characterized by two objec-
tives: throughput 𝑇(P)and resource utilization 𝑈(P). Throughput
measures the token generation efficiency (TPS), while resource
utilization reflects the fraction of available hardware resources
consumed by inference.
The goal is to maximize throughput while minimizing resource
usage. Under a fixed resource condition, this can be expressed as a
bi-objective optimization problem:

4 LaTune
The goal of LaTune is to address the tuning problem by selecting
runtime configurations that maximize throughput while adapting
to changing resource constraints on edge devices. Guided by the
three key insights, LaTune integrates focused search with the reuse
of prior results and lightweight runtime adaptation.
4.1 Overview
The workflow of LaTune is illustrated in Figure 5. First, 1 his-
torical observations are retrieved from the Historical Repository to
support the Parameter Selector. Meanwhile, 2 the meta-features
of both historical tasks and the current task (provided by the in-
ference instance) are delivered to the Knowledge Adapter, which
identifies similar tasks and retrieves their optimal configurations.
3 These transferred configurations are aligned with the current
tunable parameter set to construct candidate configurations, and 4
the resulting initial points are then passed to the Evaluator for per-
formance assessment. The Evaluator executes point initial points on
the inference instance 5 , which returns runtime metrics 6 . These
observations are used to update the Surrogate Model 7 , whose pre-
dicted mean and variance 8 are passed to the Acquisition Function
to guide exploration. New configurations proposed by the acquisi-
tion function 9 are fed back to the evaluator, forming an iterative
optimization loop. As tuning proceeds, all evaluated observations
are aggregated by the Pareto Frontier 10 to build the frontier of
optimal trade-offs. The resulting Optimal Set 11 is then passed to
the Resource-aware Selector, which finally determines 12 the optimal
configuration to deploy on the inference engine.

4.4 Two-Stage Optimization
Edge resource fluctuations caused by background activities or ther-
mal limits often render static configurations suboptimal or infeasi-
ble. Guided by Insight 3, which reveals that configuration rankings
remain stable despite such volatility, LaTune adopts a two-stage
optimization strategy. Specifically, the offline optimization stage
utilizes Multi-Objective Bayesian Optimization (MOBO) to con-
struct a diverse Pareto front of trade-offs, serving as the candidate
pool for the online adaptation stage, which dynamically selects the
throughput-maximizing configuration satisfying dynamic resource
constraints.
4.4.1 Optimal Set Construction via MOBO. In the offline optimiza-
tion stage, LaTune employs a multi-objective Bayesian optimization
(MOBO) framework [28] to construct a diverse, high-quality con-
figuration set under stable conditions. MOBO is well-suited for this
scenario as it models expensive evaluations (e.g., model loading)
through a probabilistic surrogate [11], efficiently guiding the ex-
ploration of configurations that jointly maximize throughput and
minimize resource usage.
Surrogate Model. MOBO relies on a surrogate model to approx-
imate the expensive black-box objective functions. In LaTune,
this surrogate is implemented using Gaussian Process Regression
(GPR) [45], which models each objective function 𝑓(P)as a Gauss-
ian distribution parameterized by a mean 𝜇(P)and variance 𝜎2 (P).
Given a configuration P, these parameters are estimated from previ-
ously evaluated samples, providing both a prediction and an uncer-
tainty estimate. To balance smoothness and flexibility, LaTune uses
the Matérn kernel as the covariance function. Separate GPR models
are trained for throughput and resource consumption to prevent
interference caused by different scales and correlations.
Acquisition Function. Once the surrogate model estimates the ob-
jective landscape, the next question is which configuration should
be evaluated next. To guide this exploration, LaTune adopts the
Expected Hypervolume Improvement (EHVI) acquisition function,
which quantifies how much a new candidate can expand the domi-
nated region of the current Pareto front. Formally, the EHVI is:
EHVI(x)= E [max (0,HV(𝑌 ∪{𝑓(x)})−HV(𝑌))], (8)
where HV(·)denotes the hypervolume of the dominated region in
the objective space, 𝑌 is the set of evaluated configurations, and
𝑓(x)is the predicted objective vector for candidate x. Intuitively,
configurations with higher EHVI values are more likely to improve
the trade-off front, balancing exploration of uncertain regions and
exploitation of known promising areas.
Pareto-oriented Search. The MOBO process iteratively applies
this surrogate–acquisition cycle to approximate the Pareto front of
configurations. Each iteration selects the most promising candidate
based on EHVI, evaluates it on the actual inference engine, and
updates the GPR models with the new observation. After MOBO
procedure, LaTune obtains a Pareto-optimal configuration set that
represents diverse trade-offs between throughput and resource
utilization. This front serves as a candidate pool for fast online
adaptation without repeating the heavy optimization process.

5 Experiments
We evaluate the performance of LaTune by addressing the follow-
ing research questions:
•RQ1 (Overall Performance): How does the configuration qual-
ity of LaTune compare to state-of-the-art tuning methods?
•RQ2 (Tuning Efficiency): How efficiently can LaTune identify
high-quality solutions, especially under the limited computa-
tional budget of edge devices?
•RQ3 (Ablation Study): How do the individual components,
including parameter selection, knowledge transfer, and two-stage
optimization, contribute to the system’s effectiveness?
5.1 Experimental Setup
Implementation and Environment. We implement LaTune us-
ing approximately 2.8K lines of code. The backend is llama.cpp [1],
though the design is engine-agnostic. Experiments are conducted
on diverse representative edge platforms: an NVIDIA RTX 4090 (24
GB VRAM) for high-end, an NVIDIA RTX 3060 (12 GB VRAM) for
mainstream, a Mac mini with M4 chip (16 GB memory) for Metal-
based execution, and a Jetson Orin Nano (8 GB) for low-power
embedded scenarios.
Models and Workloads. We evaluate four LLMs with different
architectures and quantization levels, including Qwen3-4B and
Phi-Mini-MoE with INT4 and INT8 quantization, to assess general-
ization across dense and mixture-of-experts models. Prompts are
sampled from the ShareGPT dataset [47] following prior work [20,
34, 43, 68]. We further define low, medium, and high load levels
using GPU utilizations of approximately 6.4%, 38.8%, and 69.9%,
respectively, induced by controlled background GPU operations.
Baselines. We compare LaTune against four representative alter-
natives to cover a range of tuning strategies.
•Default: The default configuration of the inference engine, rep-
resenting a no-tuning baseline.
•Genetic Algorithm (GA) [24]: A classic heuristic-based method.
•ResTune [70]: A state-of-the-art method that uses transfer learn-
ing and constrained Bayesian optimization for tuning.
•SCOOT [15]: A recent Bayesian optimization framework de-
signed for tuning vLLM in cloud environments.
To ensure the validity of all baselines, we conduct a thorough
review and open-source the code for community verification.
Metrics. We evaluate three metrics. Throughput is measured in
tokens per second (TPS). Resource usage is quantified as P95
VRAM consumption on NVIDIA GPUs or P95 RAM usage on uni-
fied memory platforms [29, 50, 59]. Although resource usage is
not reported explicitly, it is incorporated into the Hypervolume
(HV) metric, which measures the objective space dominated by the
Pareto-optimal configuration set [27, 69]. A larger HV indicates a
better trade-off between throughput and resource efficiency. All
results are averaged over three independent runs.
5.2 Overall Performance (RQ1)
We evaluate the quality of the final configurations identified by
LaTune against baselines, under both static offline settings and
dynamic resource constraints.
5.2.1 Quality of Optimal Configuration Sets. Table 1 presents the
HV achieved over 50 tuning iterations by each method across all
tested devices and models. A higher HV value signifies a superior
set of trade-off configurations. The results show that LaTune con-
sistently achieves the highest HV in all scenarios, demonstrating
its strong generalization capabilities. Notably, LaTune substan-
tially outperforms the Default method by a large margin, achieving
HV values that are approximately 1.47×to 3.93×higher across all
evaluated settings.

We evaluate the search efficiency of LaTune by tracking the evo-

LaTune consistently outpaces all baselines across different hard-

earlier than competitors. Specifically, LaTune rapidly converges,
reaching strong HV values within 10–20 evaluations, whereas base-
lines require 2–3×more iterations to achieve comparable or lower
results. This acceleration stems from two key mechanisms: the pa-

dominant factors, and knowledge transfer provides high-quality
initial points to warm-start the optimization.

constraints of edge devices.

6 Related Work
We situate our work within prior research on local LLM systems,
efficient inference, and automated configuration tuning.
6.1 Local LLM Inference Engines
Lightweight inference engines have enabled LLMs to run on edge
devices and consumer-grade hardware. Representative systems
include llama.cpp [1], a C++-based engine optimized for CPU and
low-level GPU execution, and MLC-LLM [53], a compiler-based
framework built on TVM [13] for cross-platform deployment. These
engines support low-bit quantization, reduce memory overhead,
and provide compatibility across hardware backends such as CPU,
CUDA, Metal, and WASM [36, 38, 63]. Compared with cloud-hosted
services, local deployment faces tight memory, compute, and power
limits. In this setting, inference parameters such as context length,
batch size, and GPU layer allocation must be carefully tuned to
avoid failures or degraded throughput.
However, existing local engines mostly rely on static configura-
tions or manual tuning. They lack automated mechanisms to adjust
runtime parameters under changing system conditions. LaTune ad-
dresses this limitation by introducing an adaptive tuning method
that automatically selects optimal configurations for local inference
engines based on current resource availability.
Siqi Zhong, Mugeng Liu, Haiyang Shen, Chongyang Pan, and Yun Ma
6.2 Efficient Inference Techniques
To improve LLM inference efficiency, researchers have proposed
both model-level and system-level optimizations. On the model
side, architectures such as Multi-Query Attention (MQA) [48] and
Grouped-Query Attention (GQA) [6, 10] reduce computation and
memory cost. Quantization techniques [35, 73] compress models
into INT8 or INT4 formats to enable deployment on resource-
limited devices with minimal accuracy loss. On the system side,
paged attention [29] and speculative decoding [31, 52, 61] reduce
memory footprint and latency for long-context generation. Prefix
caching [21, 22, 29] and continuous batching [16, 51, 65] improve
GPU utilization for multi-turn or multi-user inference.
While these techniques enhance efficiency, performance still
depends on proper configuration. Current engines integrate these
methods but cannot dynamically adapt to hardware changes. Our
work complements this by focusing on configuration-level opti-
mization: instead of modifying models, we automatically adjust
parameters to sustain high throughput under fluctuating resources.
6.3 Configuration Tuning
Configuration tuning has been widely studied in domains such
as databases [26, 56, 67], distributed frameworks [8, 12, 33], and
compilers [9, 13, 74]. Common strategies include Bayesian Opti-
mization [8, 19, 33], Reinforcement Learning [55, 67], and heuris-
tic search [60, 77], which aim to find near-optimal settings under
limited evaluation budgets. In LLM systems, SCOOT [15] applies
multi-objective Bayesian optimization to cloud workloads, and On-
lineTune [71] employs Gaussian Process-based BO for optimizing
runtime configurations in deep learning systems.
However, these studies assume static resources, making them
unsuitable for dynamic edge environments. To our knowledge,
no prior work addresses adaptive tuning for local LLMs under
time-varying constraints. We fill this gap by integrating parameter
importance analysis, multi-objective Bayesian optimization, and
runtime sensing into a unified framework.
7 Conclusion
This paper tackles the critical challenge of optimizing LLM in-
ference on resource-constrained and dynamic edge devices. We
introduced LaTune, a lightweight and adaptive tuning framework
that efficiently navigates the complex configuration space by focus-
ing on high-impact parameters, transferring knowledge from past
tasks, and dynamically adapting to resource fluctuations through a
two-stage optimization process. Our extensive experiments confirm
that LaTune significantly outperforms existing methods, finding
high-quality configurations more quickly while delivering higher
throughput and greater robustness, providing a practical solution
for efficient LLM deployment in dynamic edge environments.

LaTune: Lightweight and Adaptive Configuration Tuning for LLM Inference on Edge Devices A Appendix
A.1 Tunable Parameters in Inference Engines
As discussed in Section 2.1, modern on-device inference engines
expose a rich set of tunable parameters across different functional
layers. These parameters govern how models are prepared, ex-
ecuted, scheduled, and served, and together they determine the
overall inference efficiency in terms of throughput, latency, and
resource utilization. Following recent studies on inference engine
architecture and optimization [15, 32, 42, 58], we categorize these
parameters into four hierarchical levels according to their opera-
tional scope: model preparation, execution, system management, and
serving.
Table 2 summarizes representative parameters at each level.
Model-preparation parameters control static model transforma-
tions such as quantization or pruning, which trade accuracy for
efficiency and are typically applied offline. Execution-level param-
eters affect kernel selection, operator fusion, and memory layout
during inference. System-level parameters configure hardware re-
source usage, including the number of threads, memory pooling,
and scheduling strategies. Finally, serving-level parameters relate
to request handling, concurrency, and endpoint configuration in
multi-session deployment scenarios.
In our experiments, we focus on optimizing system-level param-
eters that directly influence runtime performance while keeping
model quality and service semantics unchanged.

A.4 Discussion and Limitations
Generalizability to Unseen Environments. LaTune may face
challenges with unseen hardware architectures where learned meta-
features are less effective. In such cases, the system degrades grace-
fully to a “cold-start” mode, ensuring functionality by accumulating
data from scratch without the warm-start advantage.
Static Parameter Selection. Our offline analysis assumes param-
eter sensitivity remains stable. Significant changes to the inference
engine or model architecture require re-triggering this analysis,
incurring a one-time cost of approximately 100 observations to
update the importance rankings.
Dependence on Ranking Stability. Our two-stage design relies
on the consistency of configuration rankings under dynamic loads.
Extreme conditions, such as severe thermal throttling, may tem-
porarily violate this assumption, suggesting a potential area for
future online recalibration mechanisms.
